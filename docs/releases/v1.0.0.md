# NeedWise v1.0.0

**2026-11-13.** Released: the [GitHub Release](https://github.com/MatamDinesh0802/NeedWise/releases/tag/v1.0.0) with SBOMs, the evaluation reports and
the release's permission-gate report, and images on GHCR, `ghcr.io/matamdinesh0802/needwise-api:1.0.0` and `ghcr.io/matamdinesh0802/needwise-web:1.0.0`
(linux/amd64 and linux/arm64, with provenance attestations). The docs are read in the
repository; there is no hosted site.
The full list of changes is in the [CHANGELOG](../../CHANGELOG.md).

## What NeedWise is

A self-hosted AI workspace for a company's knowledge. Employees ask questions in plain language
and get answers that cite their sources, drawn only from documents each of them may open.
Department agents take questions that span teams; governed tools and an MCP server put the same
answers inside Claude, Cursor and other clients; connectors keep collections in sync with Drive,
Slack, GitHub, Confluence, SharePoint/OneDrive and websites; anything that leaves the system
waits for a person's approval; meetings become decisions and tracked tasks; questions about
tabular data come back with a chart, the SQL and checked numbers. Administrators configure
agents, models and keys, budgets, document governance and the audit log without code.

It runs on Docker Compose or Kubernetes (Helm), with Claude by default or any
OpenAI-compatible server, local models included. The core is Apache-2.0; the `ee/` directory is
the commercial Enterprise edition. Everything was built and measured against Acme Robotics, a
fictional company: no real organization has run it.

v1.0.0 is the first release since v0.1.0 (Phase 1, 2026-11-04). Phases 2 to 11 were finished
on `main` without releases of their own, so this release carries all of them and Phase 12,
production hardening ([roadmap](../ROADMAP.md)).

## Highlights

### Answers and retrieval

- Streaming chat with citations to the passage, a sources panel, follow-up questions, feedback,
  usage and cost per answer, and an honest "not found" (a relevance floor answers off-topic
  questions without a model call).
- Hybrid search (dense and BM25, fused with RRF k=2 and BM25 weight 0.5, a trust boost for
  official documents), chosen by measurement: textbook fusion was worse than either input
  ([ADR 0008](../adr/0008-retrieval-fusion-and-sensitivity-routing.md)).
- Sensitivity routing: restricted sources go only to a local model, or are left out and the
  answer says so (`restricted_data: local_only` by default).
- Knowledge Hub: uploads of PDF, Word, Excel, PowerPoint, Markdown, HTML, CSV and Slack exports,
  versions, deduplication, the chunks the assistant reads, live indexing status.

### Permissions and isolation

- **Two locks on every search:** an access list on every chunk filters the vector search, then
  OpenFGA re-checks every source ([ADR 0006](../adr/0006-two-lock-permission-aware-retrieval.md)).
  Every agent, tool, workflow and MCP call acts as the person asking. Permissions are enforced in
  code, never by the model.
- **Documents' own access lists** that only narrow their collection's, enforced in both locks and
  on every other path (Community), with identity mapping for synced sources that fails closed
  ([permission sync](../permission-sync.md), [ADR 0012](../adr/0012-document-access-lists.md)).
- **Tenant isolation at every layer:** forced row-level security on every tenant table, a
  database role that cannot bypass it, tenant-prefixed Valkey keys, the tenant condition inside
  the Qdrant client, stored file keys checked, request rate limits, and a test that sends every
  route another tenant's ids ([multi-tenancy](../multi-tenancy.md)).
- A hash-chained audit log with an explorer, filters and CSV export.

### Agents, tools and MCP

- Department agents with a planner and a fast path, in plain asyncio
  ([ADR 0009](../adr/0009-orchestration-without-a-graph-framework.md)); `ASSISTANT_MODE=single`
  (the default), `auto` or `agents`.
- **Agents as configuration** ([agents](../agents.md)): collections, read-only tools, a model,
  limits, numbered versions with restore, and a test console on unsaved drafts. A Legal agent
  created in the browser with no code routes 15 of 15 legal questions.
- Governed tools with side-effect levels, a research mode that proposes actions for approval,
  an MCP client for operator-configured servers, and NeedWise as an MCP server at `/mcp` with
  personal access tokens ([MCP](../mcp.md)).

### Connectors

- Web crawler, GitHub, Google Drive and Slack (OAuth), Confluence Cloud and SharePoint/OneDrive
  (Microsoft Graph delta queries), on a sync engine with versions, deletion propagation, retries
  from the same cursor and a schedule ([connectors](../connectors.md)).
- A source health dashboard (Admin › Sources, and Knowledge Hub › Sources for collection
  owners), stale-document reminders and failing-source alerts.
- Enterprise permission sync: Drive, Slack and GitHub access lists read at every sync, Drive
  revocations from the changes feed within a minute.

### Automation and approvals

- Approvals for every action that leaves the system: an inbox, inline approval cards, edits
  re-validated, approver rules (org admins, managers, any-of groups, chains; never the
  requester), reminders and escalation, expiry ([automation](../automation.md)).
- Tasks with department queues, request routing (rules, then the router model above a threshold,
  else triage, each decision explained), email with approval, notifications by email and Slack.
- Workflows in YAML with manual, cron and event triggers.

### Meetings

- Recordings and transcripts become a summary, decisions and action items that link to the
  moment they were said, one-click tasks, "My commitments" and an indexed transcript
  ([meetings](../meetings.md)).
- Local speech-to-text (faster-whisper) and speaker diarization (sherpa-onnx, no Hugging Face
  token), naming speakers, topic outlines.

### Insights (business intelligence)

- CSV and Excel tables in a versioned DuckDB per tenant, PostgreSQL and MySQL sources read-only
  three ways, described once in a semantic layer; the BI agent queries as the person asking,
  row policies included, in a sandbox, and checks every number in its answer
  ([analytics](../analytics.md), [SQL sources](../analytics-sql-sources.md),
  [ADR 0010](../adr/0010-analytics-semantic-layer-duckdb-sqlglot.md)).

### Administration, governance and usage

- Models and providers per organization with encrypted, write-only keys, a catalog with prices,
  a model per role and per agent ([models](../models.md)).
- Every model call recorded (tokens and cost, never the text) per person, department, agent and
  feature; organization budgets and personal caps that warn or block ([usage](../usage.md)).
- Document owners, review reminders and escalation, "official" status through a second person's
  approval ([governance](../governance.md)).

### Operations

- Docker Compose with every third-party image pinned by digest; `make quickstart` to a seeded
  demo in about 3 minutes on a laptop, with the service images already downloaded
  ([quickstart](../getting-started/quickstart.md)).
- A Helm chart (0.2.0) with optional bundled dependencies, the "restricted" Pod Security Standard
  and NetworkPolicies, tested on kind clusters ([Kubernetes](../deploy/kubernetes.md)).
- Backup and restore with a measured drill ([backup and restore](../operations/backup-restore.md));
  upgrades from v0.1.0 ([upgrades](../operations/upgrade.md)); release workflows for multi-arch
  images with SBOM and provenance attestations, a scan and the permission gate before an image is
  tagged ([releasing](../operations/releasing.md)).
- Load tests with a stub model from 10 to 800 simulated users ([load benchmarks](../benchmarks/load.md)).

## Upgrading from v0.x

- **Supported:** from v0.1.0 (the only earlier tag) directly to v1.0.0. The migrations are one
  chain (`0001` to `0027`); the `migrate` service applies the missing ones before the API starts.
  Take a backup first; downgrades are not supported (restore the backup instead).
- **Tested:** on 2026-11-13 with `scripts/upgrade-test.sh v0.1.0`, a v0.1.0 stack, seeded and
  used through its API, upgraded in place to the release code: alembic `0004` to `0027`, no row
  lost, and 17 of 17 checks (the old people sign in, an access token made on v0.1.0 still works
  and finds a new upload, departments, groups and the audit chain are intact, the permission
  gate holds); `up` to healthy in 22 s, the whole test in 115 s. On 2026-11-12 the same test ran
  four times to the code of that day, and restoring a v0.1.0 backup and rolling back were tested
  ([upgrades](../operations/upgrade.md#supported-paths)).
- **What to change by hand from v0.1.0:** `SECRETS_ENCRYPTION_KEY` and `SECRETS_KEY` (refused
  in production when unset), an embedding server, a language model, outgoing mail, and the
  directories `.data/objects` and `.needwise` (`make up` creates them). Then
  `docker compose run --rm migrate nw authz sync` ([steps](../operations/upgrade.md#from-v010-manual-steps)).
- **Behaviour changes** to know about: request rate limits (429 `rate_limited`) and at most
  `MAX_INFLIGHT_PER_USER` (4) answers in progress per person; guests can no longer send email or
  create tasks for others; Slack sources sync as `discussion`; the crawler no longer follows
  redirects to other sites, and a collection owner's web source cannot reach private addresses;
  a workflow step naming an approver who no longer exists fails instead of falling back to the
  owner; the API image runs as `10001:10001`; Valkey keys moved under `t:<tenant_id>:` (an answer
  streaming during the upgrade loses its event stream).
- **Helm:** chart 0.2.0 deploys image tag `1.0.0` by default (0.1.x deployed `0.0.1`).
- The full list, per migration: the upgrade notes in the [CHANGELOG](../../CHANGELOG.md).

## Security notes

- Report vulnerabilities privately ([SECURITY.md](../../SECURITY.md)). 1.x gets
  security fixes as patch releases; 0.x does not.
- Reviewed: a [threat model](../security/threat-model.md) with ranked residual risks, a review
  against the [OWASP Top 10 for LLM Applications](../security/owasp-llm-top10.md) (11 fixes), a
  final review on 2026-11-13 (among its fixes: a collection owner's web source could reach
  internal services; repointing a source someone else had credentialed kept their credentials;
  an approver chain one person could complete), and the
  [supply chain](../security/supply-chain.md) (osv-scanner, Trivy, hadolint, actionlint, zizmor,
  CodeQL, SBOMs; images and actions pinned). Each fix has a regression test.
- Not done: an external penetration test. The security workflows first ran on GitHub on
  2026-11-13 and passed.
- Known residual risks: prompt injection is mitigated, not solved (a document can still steer
  what a model writes within what the person may see); a malicious organization admin is audited,
  not prevented; one deployment key encrypts all tenants' secrets; streamed tokens are not
  sanitized (the stored answer is). The [threat model](../security/threat-model.md#5-residual-risks-ranked)
  ranks them.

## Known limitations and what is not built

- **Not verified against live services:** Google Drive, Slack, Confluence and SharePoint/OneDrive
  sync and Enterprise permission sync were tested against fakes of their documented APIs (the web
  crawler and GitHub against live sites).
- **Not tested:** a cloud Kubernetes cluster, TLS, managed databases; load with a real model or
  many tenants; execution accuracy on a PostgreSQL or MySQL source with a real model; topic
  outlines and extraction from diarized recordings with a real model; any model other than
  Claude Sonnet 5.5 (and Opus 5.5 for some suites).
- **Small, synthetic evaluation:** 49 documents (the plan was about 500), 82 QA questions, 68
  attacks, written by the people who built the system; fusion settings and prompts were tuned on
  the same questions.
- **Designed but not built:** metrics and alerts, S3 storage (a local directory only), invitations
  by email, a reranker, a provider fallback chain, SCIM and DLP, a Slack or Teams bot, Microsoft
  Teams notifications, a screen for a document's own list, and the rest of the list in
  [ARCHITECTURE](../ARCHITECTURE.md#what-the-design-describes-that-is-not-built).
- **Not done for the launch:** the public repository (so no GitHub Release, published images or
  hosted docs), the public demo deployment, and the launch posts.

## Editions

- **Community** (everything outside `ee/`, Apache-2.0): the whole product above, security basics
  included: both permission locks, documents' own access lists, row-level security, the audit log,
  legal holds enforced on every deletion path, the evaluation and red-team suite.
- **Enterprise** (`ee/`, commercial license, active only with a signed license key): department
  budgets, the chargeback report, retention policies and document retention, the audit export for
  a SIEM, per-document permission sync from Drive, Slack and GitHub, and placing legal holds
  ([enterprise](../enterprise.md)). Without a license these answer `402 enterprise_feature`. The
  API image includes the package, inactive without a license.
